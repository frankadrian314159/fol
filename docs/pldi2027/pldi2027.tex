\begin{abstract}
Persistent-first languages pay a large allocation tax on accumulation loops. Languages like Koka eliminate it with ownership types (Perceus/FBIP); Clojure asks the programmer to opt in manually with transients. We show the optimization can be made \emph{automatic and sound} in a latently-typed language with open-world CLOS dispatch and live redefinition---with no type system---via (1) a tail-position-sensitive \emph{usage classification} that establishes uniqueness-at-death of loop and fold accumulators, (2) a rewriter aligned with the classifier \emph{by construction}, targeting edit-tagged in-place transients, and (3) \emph{world-guarded regions} that keep the optimization sound when definitions change at runtime. On large accumulation-bound loops, conversion delivers 3.4--4.3$\times$ wall-time and 8.7--11$\times$ allocation improvements (89--97\% of the wall-time gain attributable to transient conversion alone, isolated by ablation), closing 72--79\% of the gap to handwritten mutable Common Lisp. Whole programs spanning word-frequency counting, sorting, and graph traversal see 1.6--3.5$\times$; small-N accumulations a modest but real 1.3$\times$. A real-representation ablation---exercising an actual alternative implementation, not a simulated cost model---shows wrapper-style transients match ours on write-only workloads at every scale, losing only where they structurally cannot compete: read-heavy accumulation, which they cannot serve at all. We report negative results with the same rigor as positive ones: a nontrivial event simulator produces byte-identical output but \emph{regresses} under conversion, a real, measured instance of our own cost model's small-N caveat rather than a soundness issue, and the technique costs nothing when disabled or inapplicable.
\end{abstract}

\section{Introduction}

Persistent data structures offer immutability and thread-safety at a "persistence tax": every update allocates a new version from the root, turning accumulation loops into excessive allocation and GC pressure.

In FOL, the cost is stark: simple accumulation loops run up to 114× slower than handwritten, mutable Common Lisp (55× more memory), worse for loops threading an accumulator through user-defined helpers---our Derived Value Invalidation (DVI) benchmark: 20× slower, \textbf{900×} higher in memory, from O(N²) GC pressure. This paper presents a sound, automatic optimization eliminating the tax for a large class of \emph{intraprocedural} accumulation loops, using interprocedural DVI as an unsolved boundary condition delineating scope and motivating future work.

The pattern suffering this tax: the accumulation loop, common to \texttt{loop/recur} and \texttt{reduce}:

\begin{lstlisting}
;; Loop-based accumulation
(loop [acc {}]
  ...
  (recur (assoc acc k v)))

;; Fold-based accumulation
(reduce (fn [acc x] (conj acc ...))
        [] coll)
\end{lstlisting}

Each iteration's \texttt{assoc} or \texttt{conj} call allocates a new map or vector, discarding the old: if the old \texttt{acc} produces only the new \texttt{acc}---unique at its point of death---the update can happen in-place.

Existing solutions don't transfer to FOL. Perceus/FBIP \cite{reinking2021perceus} and its relatives \cite{lorenzen2023functional} rely on ownership and uniqueness types, absent here. Clojure \cite{hickey2009clojure} offers a manual, unsafe escape hatch---\texttt{transient} structures and \texttt{assoc!}-style updates---where misuse corrupts data. FOL also supports live redefinition, so an optimized loop's assumptions may be invalidated \emph{mid-run}.

We present a fully automatic, sound system converting persistent accumulation loops to in-place transients. Contributions:

\begin{enumerate}
    \item \textbf{Uniqueness-at-death by usage classification.} A flow- and tail-position-sensitive classification of accumulator uses (\texttt{:recur-update}, \texttt{:exit-bare}, etc.) establishing in-place convertibility---without ownership or linear types---including \texttt{->} threads, if-branches, and \emph{reduce init-threading}.
    \item \textbf{Alignment-by-construction between analysis and transformation.} The classifier refuses anything the rewriter can't reach (\texttt{:recur\_in\_complex\_context}) or that changes representation mid-loop (\texttt{:recur\_reset}); per-representation \emph{op gates} are classification-time, not runtime, so converted code never hits an unsupported operation.
    \item \textbf{Name-resolution-faithful, two-tier summaries.} Tier-1 matches operators exactly as the compiler resolves them (by name)---no less sound than the language's own resolution model. Tier-2 extends coverage to user functions, inferring summaries over the same lattice via a bounded fixed point, invalidated on redefinition (§\ref{sec:tier2}).
    \item \textbf{Soundness under live redefinition without world-age infrastructure.} Converted regions compile to guarded dual paths; validity cells register at load time; definitions notify at execution time, invalidating dependents. Guards measure as free. This closes redefinition \emph{after} a region registers a dependency; we additionally found and closed a gap on the other side---a \texttt{:before}/\texttt{:after}/\texttt{:around} method already present on an assumed name \emph{before} any region ever depended on it produces no redefinition event to catch, so its behavior was silently dropped by the bang-op fast path. A compile-time MOP check on the live generic function closes this (§\ref{sec:formal}), confirmed by reproducing the exact failure it fixes.
    \item \textbf{An honest cost model} quantifying when conversion pays. Wrapper transients (O(n) boundaries) turn out to match our edit-tagged transients (O(1)/O(32)) on write-only workloads at every scale we measured, large or small-N (§\ref{sec:eval}, RQ5)---the boundary-cost gap the design targets amortizes away within a single session; edit-tagged's decisive, measured advantage is instead structural: it is the only one of the two that can serve a read at all, extending conversion to read-heavy folds wrapper transients cannot reach by construction. Validated on DVI (accumulation flows through a helper beyond the client's reach, §\ref{sec:discussion}) and an end-to-end system bounded by factors this technique doesn't address.
\end{enumerate}

Our contribution is not a new escape analysis but assembling name-resolution-faithful summaries and world-guards into automatic, sound transient conversion for a \emph{dynamic, open-world, JIT-less} language---distinct from static-language (closed-world, typed) and JIT-based approaches (infrastructure FOL lacks).

Our evaluation shows 3.4--4.3× wall-time and 8.7--11× allocation on large accumulation-bound microbenchmarks, closing 72--79\% of the gap to handwritten mutable Common Lisp; §\ref{sec:eval} isolates transient conversion's own share of that via ablation at 89--97\%. Small-N accumulations see a modest 1.3×---a real ablation (RQ5) shows wrapper-style transients match ours on write-only loops at every scale there, losing only on reads, which they cannot serve at all. Whole programs (quicksort, word-count, bfs-ranks) see 1.6--3.5×, with the inconvertible quicksort style correctly refused. A nontrivial event simulator produces byte-identical, but not faster, results: it regresses under conversion (§\ref{sec:eval}, RQ6), a real instance of the cost model's own small-N caveat, not a soundness issue. Overhead is negligible when the technique is disabled or inapplicable (§\ref{sec:eval}).

\section{Background and a Motivating Walk-through}
\label{sec:background}

\textbf{Terms at a glance.} This paper introduces several mechanism names used throughout; a reader can skip this and look terms up on first encounter (each is defined again where introduced), but for reference:
\begin{description}
    \setlength{\itemsep}{0pt}
    \item[\emph{uniqueness-at-death}] no alias to an accumulator's current value survives past its use---the property licensing in-place mutation (§\ref{sec:analysis}).
    \item[\emph{chain / spine}] a syntactic sequence of update operations threaded onto an accumulator (e.g.\ \texttt{->} calls); the \emph{spine} is the set of operator names in it (§\ref{sec:chains}).
    \item[\emph{Tier-1 / Tier-2}] the hand-verified stdlib summary table, vs.\ inferred summaries for user functions (§\ref{sec:tier1}--\ref{sec:tier2}).
    \item[\emph{op gate}] the per-representation table of which spine operators a transient supports (§\ref{sec:opgates}).
    \item[\emph{edit-tagged}] our transient design: trie nodes carry a per-session ownership token, enabling O(1)/O(32) writes and mid-session reads (§\ref{sec:edittagged}).
    \item[\emph{world guard}] the runtime validity-cell mechanism keeping conversion sound under live redefinition (§\ref{sec:soundness}).
    \item[\emph{alignment-by-construction}] the classifier and rewriter share the same predicates, so nothing the classifier accepts is unreachable by the rewriter (§\ref{sec:formal}).
\end{description}

\textbf{FOL in one column.} FOL is a Lisp-1 transpiled to Common Lisp, with persistent data structures: vectors are 32-way tries; dictionaries are Hash Array Mapped Tries (HAMTs) \cite{bagwell2001ideal}. \texttt{(loop [bindings] ... (recur new-vals))} gives tail-call-optimized looping; \texttt{->} threads an expression through forms; \texttt{reduce} folds a function over an accumulator and successive items. The compiler resolves standard-library calls by name at emit time---load-bearing for our analysis (§\ref{sec:nameres}).

\textbf{Worked Example.} \texttt{lh-pop-batch}, from LSim, builds a priority queue via \texttt{conj}.

\emph{Original Code:}
\begin{lstlisting}
(defn lh-pop-batch [q n]
  (loop [acc [] i 0]
    (if (< i n)
      (let [[v new-q] (pop q)]
        (recur (conj acc v) (inc i)))
      [acc q]))) ; Exit with acc in a literal
\end{lstlisting}
Each \texttt{conj} call creates a new persistent vector, copying the root path. Our analysis identifies \texttt{acc} as a candidate: fresh (\texttt{[]}), never escaping, used in the \texttt{recur} call and exit literal (sanctioned).

\emph{Converted Code:}
\begin{lstlisting}
(defn lh-pop-batch [q n]
  (if (is-valid? *lh-pop-batch-region-1*)
    ;; Fast path
    (loop [acc-t (transient []) i 0]
      (if (< i n)
        (let [[v new-q] (pop q)]
          (recur (conj! acc-t v) (inc i)))
        [(persistent! acc-t) q]))
    ;; Slow/fallback path
    (loop [acc [] i 0]
      ... ; Original code
      )))
\end{lstlisting}
The compiler emits a dual-path version: the fast path uses \texttt{transient}/\texttt{conj!}/\texttt{persistent!} for O(1) conversion, guarded by \texttt{is-valid?}---redefining \texttt{conj} triggers the fallback.

\textbf{Clojure Transient Recap.} Clojure's transients give a mutable, in-place view over a collection, but reads are problematic: a read might miss an update. "Wrapper" transients forbid reads; "edit-tagged" ones (ours) support reads too (§\ref{sec:edittagged}), suiting read-heavy algorithms like folds.

\section{The Analysis}
\label{sec:analysis}

We aim to prove \emph{uniqueness-at-death}: each iteration's accumulator value produces only the next iteration's value, and the final value shares identity with nothing else live---stronger than escape analysis, which only asks whether a value \emph{may} escape.

\subsection{Two Properties: Escape vs. Uniqueness-at-Death}

\begin{itemize}
    \item \textbf{Escape (May-analysis):} An object \emph{escapes} if its lifetime exceeds static scope---enabling stack allocation.
    \item \textbf{Uniqueness-at-Death (Must-analysis):} An object is \emph{unique at death} if no aliases exist at its last use:
    \begin{enumerate}
        \item \textbf{Freshness:} the initial value is fresh, unaliased.
        \item \textbf{No-aliasing:} No new aliases outlive the iteration (e.g., a global or captured variable).
        \item \textbf{Last-use:} The \texttt{recur}/\texttt{reduce} update is the value's final use in the iteration.
    \end{enumerate}
\end{itemize}

If these hold, mutation is safe.

\subsection{Tier-1 Summaries: The Effect Lattice}
\label{sec:tier1}

Tier-1 summaries cover the standard library, classifying each function's effect on its arguments---particularly the accumulator---over an effect lattice:

\texttt{:none} $<$ \texttt{:invoked} $<$ \texttt{:shared-with-result} $<$ \texttt{:retained}

\begin{itemize}
    \item \texttt{:none}: unused.
    \item \texttt{:invoked}: called, not retained.
    \item \texttt{:shared-with-result}: may appear in the return value (e.g., \texttt{(identity acc)}).
    \item \texttt{:retained}: escapes to a persistent location (e.g., \texttt{(add-watch! acc ...)})---a disqualifier.
\end{itemize}

We hand-verified ~75 core-function summaries. The key insight, \textbf{root-level convention}: persistent operations like \texttt{assoc}/\texttt{conj} return a fresh root that may reference unchanged children. Since our protocol is copy-on-write and never mutates elements, this holds for all clients, including transients.

\subsection{Name-Resolution Faithfulness}
\label{sec:nameres}

A summary for \texttt{assoc} is useless if shadowable: \texttt{fol.core} exports nothing, so a user's \texttt{assoc} may be local or another library's---resolved via a lookup list (\texttt{+standard-fol-functions+}) unless shadowed.

Our analysis mirrors this, consulting the Tier-1 table only for identically-resolved names, with per-compilation-unit exclusions (\seqsplit{\texttt{*file-function-defs*}}):

\begin{lemma}[Name-Resolution Faithfulness]
\label{lem:nameres}
Any program for which the analysis misjudges a function's effect (by applying a summary to the wrong function) is a program where the compiler itself would have resolved the name to the same, wrong function. The analysis is no less sound than the language's own resolution model.
\end{lemma}

\begin{proof}
The emitter and the analysis gate on the same predicate: a name $n$ resolves to the standard library iff $n$ appears in \texttt{+standard-fol-functions+} and isn't locally excluded. The analysis consults the summary table only under this predicate; the emitter resolves each call under the same predicate and exclusions. Hence any summary applied to the wrong function was resolved to that same wrong function by the emitter too---the divergence lies in the program's shadowing, not the analysis.
\end{proof}

\subsection{Tier-2: Inferred Summaries for User Functions}
\label{sec:tier2}

Tier-1 covers the standard library, but accumulators thread through user-defined helpers, e.g.\ \texttt{(recur (add-item acc x) ...)}. Without a summary for \texttt{add-item}, the analysis must treat the call as \texttt{:retained}. Tier-2 closes this \emph{knowledge} gap by inferring summaries for user functions over the same lattice---but not the \emph{update-chain} gap; see §\ref{sec:discussion} and RQ3.

A second, independent path isn't gated on this: the Qualification Rule's ``constructor call summarized as returning an unaliased root'' clause (§\ref{sec:formal}) accepts a loop initializer that's a \emph{call}, not only a literal, whenever the callee's summary proves \texttt{:returns-fresh-p} with a known result representation (dict/vector/set). A user-defined 0-ary constructor's summary can only come from Tier-2---no Tier-1 entry exists---so Tier-2 alone converts loops a literal-only check would reject, independent of the gap above (RQ3).

Compiling a definition walks its body in one pass, joining an effect per parameter: an argument to a callee with a known summary contributes its per-argument effect; a tail-position return contributes \texttt{:shared-with-result} (not fresh); closure capture or flow into an unsummarized call contributes \texttt{:retained}. Calls to not-yet-summarized functions---including self- and mutual recursion---are resolved by iterating to a \emph{fixed point}: each round re-runs with the previous summaries until stable. Since the lattice is finite and joins are monotone, the iteration converges; a small bound guards against pathologies; non-convergence leaves the function unsummarized, conservatively (RQ3 validates both cases).

Inferred summaries are consulted like Tier-1's, inheriting name-resolution faithfulness (§\ref{sec:nameres}): cached under the names the compiler resolves. Soundness under redefinition uses the same mechanism as §\ref{sec:soundness}: the notification emitted when a definition executes both flips dependent validity cells \emph{and} evicts the redefined name's inferred summary, so stale inferences can't outlive their code.

\subsection{The Classifier}

FOL supports user-defined macros (\texttt{defmacro}); expansion is inlined into parsing, so by the time the classifier walks a form, every macro---user- or library-defined---is already expanded. The classifier thus sees exactly the code that runs, so aliasing hidden in a macro expansion needs no separate, macro-aware handling.

The classifier walks the loop body, assigning each accumulator-candidate appearance a usage kind via sanctioned uses:
\begin{itemize}
    \item \textbf{Tail-position propagation:} Tracked through \texttt{if}/\texttt{do}/\texttt{let}/\texttt{case}/\texttt{cond}; a tail-position accumulator is exit-eligible.
    \item \textbf{Literals:} An accumulator inside a literal (\texttt{[acc]}, \texttt{\#\{acc\}}) is a sanctioned exit if the literal is in tail position.
    \item \textbf{Recur handling:} An accumulator in \texttt{recur} argument position is \texttt{:recur-update} if part of a sanctioned chain.
    \item \textbf{Reads:} An accumulator in argument position 0 of a whitelisted read-only function (e.g., \texttt{get}, \texttt{count}) is \texttt{:read-ok}; as a map-lookup \emph{key} it disqualifies, since mutation would violate value semantics.
    \item \textbf{Disqualifiers:} Any non-sanctioned use (e.g., an unknown function, closure storage) disqualifies the candidate---notably:
    \begin{itemize}
        \item \texttt{:recur\_reset}: resets to a value not derived from the old one (e.g., \texttt{(recur \{\} ...)}), requiring a mid-loop representation change.
        \item \texttt{:recur\_in\_complex\_context}: the \texttt{recur} itself is reached through an AST node type the classifier (and rewriter) share no explicit clause for---e.g.\ a \texttt{recur} inside a \texttt{handler-case}, which the rewriter would have to reproduce verbatim rather than rewrite beneath. (An if-branched update chain, \texttt{(recur (if p (assoc acc k v) acc) ...)}, is \emph{not} this case---§\ref{sec:formal}'s \textsc{chain-if} plus \textsc{chain-id} accept it directly, as \textsc{recur-update}.)
    \end{itemize}
\end{itemize}

\subsection{Chains}
\label{sec:chains}

Update chains are operations threading the accumulator linearly; the classifier recognizes:
\begin{itemize}
    \item \textbf{Direct calls:} \texttt{(assoc acc k v)}
    \item \textbf{\texttt{->} threads:} \texttt{(-> acc (assoc k v) (dissoc k2))}
    \item \textbf{If-branched chains:} \texttt{(if test (assoc acc k v) (dissoc acc k2))}, both branches valid.
    \item \textbf{Reduce init-threading:} A \texttt{reduce} form is a valid chain link if its accumulator threads linearly. For \texttt{(reduce f init-val coll)}, if \texttt{init-val} chains on the outer accumulator and \texttt{f} qualifies under fold rules (its accumulator used linearly, not capturing the outer one), the \texttt{reduce} is a single \texttt{:update} link.
    \item \textbf{Helper inlining:} A call \texttt{(helper acc k)}, where \texttt{helper} is a previously-compiled, single-clause user function whose body is itself a chain rooted at its accumulator-position parameter, is substituted and re-classified---so \texttt{(recur (add-item acc x) ...)} converts through \texttt{add-item} as if inlined. A parameter referenced more than once in the helper's body (the read-heavy shape, e.g.\ \texttt{(assoc cart k (inc (get cart k 0)))}) still inlines when that argument is cheap to duplicate (a bare variable or literal); the helper's name becomes a world-guard dependency of the region (§\ref{sec:soundness}). Inlining only fires where the classifier already looks for a chain---a recur argument or the loop's tail position---not an arbitrary call elsewhere in the body (§\ref{sec:discussion} discusses this limit).
\end{itemize}

\subsection{Formal Core}
\label{sec:formal}

The lemma and theorem below are hand-checked, not machine-mechanized, formalizing enough of the calculus for precision and auditability, not a Coq/Agda artifact. The analysis works over a core calculus with judgment $\Gamma; \Sigma \vdash e \Downarrow U$: in context $\Gamma = (\tau, acc)$, $\tau \in \{\mathsf{Tail}, \mathsf{NonTail}\}$ tracking whether $e$'s value flows to the loop's exit; $e$ has usage set $U$ given operator summaries $\Sigma$. $\Gamma_{\mathsf{NT}}$ forces $\tau$ to $\mathsf{NonTail}$. Three side-condition predicates are used: $\mathrm{Chain}(e', acc)$, $\mathrm{RefersTo}(e, acc)$, and $\mathrm{OpGate}(e', acc)$. Unlike the rest of this section, these were prose-only in an earlier draft; Figure~\ref{fig:side-conditions} now gives each an inductive definition, so nothing the judgment below depends on is left unformalized. $\mathrm{Chain}$ is syntactic pattern recognition, deriving alongside it the \emph{spine} of update operations threaded onto $acc$; $\mathrm{OpGate}$ is the one representation-specific, semantic check---it holds iff that spine is executable by some transient representation's counterpart operations, so \textsc{recur-update} below matches only chains the rewriter can carry out, not merely parse. \texttt{let}/\texttt{case}/\texttt{cond} desugar like \textsc{if}/\textsc{do} below (tail position threads to the last or selected branch); omitted for space. The rules are tried in order (Figure~\ref{fig:formal-rules}); \textsc{none}/\textsc{escape} are fallbacks when no rule above matches, making the judgment total and deterministic over every subexpression of the loop body.

\textsc{read}/\textsc{recur} are the only rules inspecting a specific argument position; an occurrence of $acc$ anywhere else---an argument to an unsummarized call, a closure body, a map key---falls through every rule above \textsc{escape}: \textsc{none} doesn't apply ($\mathrm{RefersTo}$ holds), and no earlier rule matched. This is \texttt{:escape} in the vocabulary below, now derived rather than asserted.

The full use vocabulary---no unlisted cases, every tag below produced by one rule above---is:

\emph{Sanctioned uses} (the set \emph{SanctionedUses}):
\begin{description}
    \item[\texttt{:recur-update($e'$)}] $acc$ is consumed by an update chain $e'$ (§\ref{sec:chains}) whose result flows to $acc$'s \texttt{recur} position, every operation in $e'$ executable per $\mathrm{OpGate}(e', acc)$. The implementation further labels the zero-op case---$e'=acc$ itself, a recur that carries the accumulator through untouched this iteration---\texttt{:recur-passthrough} for diagnostics; formally both instantiate \textsc{recur-update}, the zero-op case licensed by \textsc{chain-id} (Figure~\ref{fig:side-conditions}).
    \item[\texttt{:exit-update($e$)}] $acc$'s update chain $e$ is itself in tail position, not wrapped in a \texttt{recur}---the shape a \texttt{reduce} callback's body takes (\texttt{(assoc acc w (inc (get acc w 0)))}, word-count's own qualification, §\ref{sec:eval}) and \texttt{:reduce} mode's per-iteration return value generally.
    \item[\texttt{:exit-bare}] $acc$ is returned directly, in tail position (a sanctioned exit).
    \item[\texttt{:exit-in-literal}] $acc$ is returned inside a collection literal in tail position.
    \item[\texttt{:read-ok}] $acc$ appears in argument position 0 of a whitelisted read-only operation.
\end{description}

\emph{Disqualifying uses} (any occurrence forces $\neg$\emph{Qualifies}):
\begin{description}
    \item[\texttt{:recur-reset}] a \texttt{recur} rebinds $acc$ to a value not derived from it (representation would change mid-loop).
    \item[\texttt{:recur-in-complex-context}] the update expression is outside the rewriter's grammar, or a recognized chain uses an operation with no transient counterpart in its op gate (§\ref{sec:opgates})---e.g.\ \texttt{assoc} on a vector, whose gate admits only \texttt{conj!}.
    \item[\texttt{:escape}] otherwise: an unsummarized call argument (or summarized \texttt{:retained}/\texttt{:shared-with-result} in a non-chain position), closure capture, storage into a structure outside a sanctioned exit, or a map key/set element (mutation would violate value identity). The implementation labels several of these with more specific diagnostic tags for the audit report (§\ref{sec:implementation})---\texttt{:captured} (closure body), \texttt{:other-flow} (a bare non-tail, non-argument occurrence), \texttt{:shadowed-bind} (a \texttt{bind} rebinds the name, a standard hygiene concern this calculus otherwise leaves implicit, as is typical for operational semantics presentations), \texttt{:nested-loop-init} (flows into a nested loop's bindings), \texttt{:escape-call} (an unsummarized call argument), \texttt{:read} (a summarized-but-not-transient-whitelisted read)---all formally \texttt{:escape}; §\ref{sec:implementation} documents the verified correspondence.
\end{description}

\emph{Qualification Rule:}
\[
\frac{\Gamma \vdash \text{init fresh} \quad \forall u \in \text{uses}(\text{body}, acc),\ u \in \text{SanctionedUses}}{\text{Qualifies}(\texttt{loop [acc init] body})}
\]
where \emph{init fresh} holds when the initializer is a collection literal or a constructor summarized as returning an unaliased root---§\ref{sec:tier1}'s root-level convention licensing \texttt{assoc}/\texttt{conj}'s fresh-root return---and $\mathrm{uses}(\mathrm{body}, acc) = U$ such that $\Gamma_0; \Sigma \vdash \mathrm{body} \Downarrow U$ with $\Gamma_0.\tau = \mathsf{Tail}$ (the loop body's tail position is its exit point)---i.e.\ \emph{uses} is the judgment above.

\textbf{Trusted assumptions.} The soundness results are conditional on three explicitly trusted components:
\begin{description}
    \item[(A1) Summary soundness.] Each Tier-1 summary correctly bounds its library function's argument effects. Tier-1 is a hand-verified trusted base (\textasciitilde75 entries), package-lock-protected against accidental modification---holding even if the \emph{library functions the table describes} (\texttt{assoc}, \texttt{conj}, etc.) are redefined at runtime, a threat §\ref{sec:soundness} defends against. Tier-2 summaries derive from Tier-1 via §\ref{sec:tier2}'s monotone inference and inherit its trust. A narrower claim than it first appears: a Tier-1 summary describes only a generic function's \emph{primary} method, the root-rebuild behavior common to every collection of that kind. CLOS permits attaching \texttt{:before}/\texttt{:after}/\texttt{:around} methods to \texttt{assoc} (or any Tier-1 name) specialized on a \emph{particular} representation class, injecting behavior the summary says nothing about; \texttt{ASSOC!} has no connection to \texttt{ASSOC}'s method combination, so such behavior would be silently skipped by the fast path. §\ref{sec:soundness}'s world guard does not close this by itself: \texttt{NOTE-REDEFINITION} fires on every \texttt{defmethod}, so a qualifying method added \emph{after} a region registers a dependency on the name is correctly caught---but a method that already existed beforehand produces no redefinition event for a not-yet-registered dependent to observe. We found this gap by direct reproduction, not inspection: attaching a logging \texttt{:around} method to \texttt{assoc} for \texttt{<dict>} \emph{before} compiling an otherwise-ordinary qualifying loop, the converted loop's fast path called the logger zero times over a run that should have called it $N$ times. The fix, now enforced rather than merely assumed: before accepting a conversion, \textsc{recur-update}'s $\mathrm{OpGate}$ premise additionally requires, via MOP introspection on the \emph{live} generic function, that the accumulator's resolved representation class have no non-primary-qualified method on any assumed name (\texttt{TIER1-METHODS-TRUSTED-P}, escape-analysis.lisp)---the one point in the system where a formally "syntactic" side condition (§\ref{sec:formal}) must consult mutable ambient state, since the hazard \emph{is} ambient state no AST walk can see. A1 is accordingly true by construction for every conversion this system actually performs, not merely assumed of the input program.
    \item[(A2) Transient-protocol correctness.] Each transient operation \texttt{op!} on an unaliased collection is observationally equivalent to \texttt{op} plus discarding the input, and \texttt{persistent!}$\circ$\texttt{transient} is the identity---the edit-token implementation's contract (§\ref{sec:edittagged}), exercised per the ownership test suite. This reduces to one invariant: each live transient region mints a globally-unique token, so a node's tag identifies at most one owning region, and \texttt{ensure-editable}'s copy-on-mismatch rule (§\ref{sec:edittagged}) never lets two live regions mutate the same interior node. Lemma~\ref{lem:classifier} supplies uniqueness of the accumulator's \emph{root}; A2 extends that guarantee to the interior nodes it may reference.
    \item[(A3) Resolution faithfulness.] Names are resolved as modeled---which is Lemma~\ref{lem:nameres}, discharged above.
\end{description}

\begin{lemma}[Classifier Soundness]
\label{lem:classifier}
Assume A1 and A3. If \emph{Qualifies}(\texttt{loop [acc init] body}), then in every execution of the loop, at each \texttt{recur} the current accumulator value is referenced only by the loop binding itself (uniqueness-at-death), and at each exit the escaping value is referenced only by the exit expression.
\end{lemma}

\emph{Proof sketch.} By induction on iterations, with the invariant that the loop binding is the accumulator's sole live reference. The base case is the freshness premise. For the inductive step: by qualification, each occurrence of $acc$ in the body is a sanctioned use. A \texttt{:read-ok} use passes $acc$ to an operation whose summary (A1, via A3) guarantees the argument is neither retained nor shared with the result, so no reference survives the call. A \texttt{:recur-update} consumes $acc$ in a chain whose every link returns a fresh root without retaining its input (by summary); \texttt{recur} rebinds the binding to the chain's result, re-establishing the invariant (the zero-op case, \textsc{chain-id}, trivially preserves it: the binding is rebound to itself). An \texttt{:exit-update} is the same argument at the loop's own tail position rather than \texttt{recur}'s: the chain's result is fresh by the same summary reasoning, and it is this fresh value, not $acc$'s old binding, that becomes the escaping result. Exits (\texttt{:exit-bare}, \texttt{:exit-in-literal}, \texttt{:exit-update}) terminate the loop, transferring the sole reference to the exit expression. Since qualification excludes disqualifying uses and the vocabulary is exhaustive over $acc$'s occurrences, no alias-creating use exists. $\square$

\emph{Remark (non-local exits).} FOL, transpiling to Common Lisp, inherits the host's condition system for non-local exit. A condition signaled mid-chain, unwinding past the loop's \texttt{recur}, doesn't threaten the invariant: the transient is reachable only through the loop's local binding, and any handler observing it would need a use of $acc$ outside \emph{SanctionedUses}---a closure capture or external store, both \texttt{:escape}---which qualification already excludes. An unwound loop simply abandons its transient, unreachable and collected like any other garbage.

\begin{theorem}[Soundness of Conversion]
\label{thm:sound}
Assume A1--A3. If \emph{Qualifies}(\texttt{loop [acc init] body}), then replacing the persistent operations on \texttt{acc} with their transient counterparts and inserting \texttt{persistent!} at all exits yields a program observationally equivalent to the original.
\end{theorem}

The proof proceeds by a bisimulation: Lemma~\ref{lem:classifier} supplies the uniqueness invariant the bisimulation maintains, and A2 supplies the per-step equivalence of each rewritten operation. The theorem's conclusion presupposes ``their transient counterparts'' is well-defined, i.e.\ every persistent operation \emph{Qualifies} admits on \texttt{acc} has one; the $\mathrm{OpGate}$ premise of \textsc{recur-update} (§\ref{sec:formal}) guarantees this by construction for every \emph{Qualifies}-accepted occurrence---so the replacement is total over the qualifying program, not merely where available. The transient implementation's ownership tokens (§\ref{sec:edittagged}) discharge the interior-node-sharing obligations; the detailed sketch is in Appendix A.

\section{The Transformation and the Transient Representation}
\label{sec:transformation}
\subsection{The Rewriter}
Once qualified, the rewriter transforms the loop.
\begin{enumerate}
    \item \textbf{Initialization:} the binding is wrapped in \texttt{(transient ...)}.
    \item \textbf{Update Chains:} Each \texttt{recur} update becomes its "bang" equivalent (e.g., \texttt{assoc} → \texttt{assoc!}).
    \item \textbf{Exits:} Every exit (bare, in a chain, or in a literal) is wrapped in \texttt{(persistent! ...)}.
    \item \textbf{Modes:} Operates in \texttt{:loop} or \texttt{:reduce} mode; in the latter, the transient threads through without persistent! boundaries, optimizing folds.
\end{enumerate}
It preserves sharing for unmodified subtrees.

\subsection{Per-representation Op Gates}
\label{sec:opgates}
Not all persistent collections have full-featured transients. Our rewriter enforces this with \emph{op gates}, checking the accumulator's operations against its type's allowed set before converting:
\begin{itemize}
    \item \textbf{Dicts:} \texttt{\{assoc!, dissoc!\}} + reads (\texttt{get}, \texttt{contains?}, etc.)
    \item \textbf{Vectors:} \texttt{\{conj!\}} + reads
    \item \textbf{Sets:} \texttt{\{conj!, disj!\}} + reads---\texttt{<set>} is HAMT-backed exactly like \texttt{<dict>} (§\ref{sec:edittagged}), not a separate representation, so it gets the identical edit-tagged treatment and the same read support.
\end{itemize}
If a loop uses an unsupported operation (e.g.\ \texttt{assoc} on a vector accumulator, whose gate admits only \texttt{conj!}), the chain is incompatible, leaving the loop unconverted. This isn't merely a rewriter-side safety net: it's the $\mathrm{OpGate}(e', acc)$ predicate \textsc{recur-update} requires (§\ref{sec:formal}), so a chain using an absent operation is never classified \texttt{:recur-update}---it falls to \texttt{:recur-in-complex-context} and disqualifies. Converted code thus never hits an unsupported operation, by construction.

\subsection{Edit-tagged Transients}
\label{sec:edittagged}
Our implementation uses edit-tagged transients, inspired by Clojure.
\begin{itemize}
    \item \textbf{HAMT (Dicts/Sets):} Trie nodes carry an "edit" token; creating a transient mints one. On a write, \texttt{ensure-editable} checks the tag: a match updates in-place; otherwise it's copied, tagged, and mutated. \texttt{persistent!} freezes the transient by clearing the token, making nodes read-only.
    \item \textbf{Vectors:} A transient vector has an owned, mutable tail array; \texttt{conj!} appends to it. On overflow, a new tail is allocated and the path updated via HAMT copy-on-write, giving O(1) appends at O(32) boundary-crossing cost.
    \item \textbf{Transient-aware Reads:} A persistent lookup function will \textbf{silently misread} an edited transient, skipping copied-on-write nodes. Our read operations (\texttt{get}, \texttt{count}, etc.) are transient-aware: they accept both collections, dispatching to the correct lookup function (\texttt{hamt-get-transient}, \seqsplit{\texttt{\%transient\_vec\_t\_ref}}).
\end{itemize}

\subsection{Dynamic-extent Closures}
As an optimization, we identify closures with dynamic extent: a literal \texttt{fn} passed to a verified non-retaining, higher-order function (\texttt{map}, \texttt{reduce}) can be stack-allocated. World-guarded: redefining \texttt{map} as retaining would leave a dangling stack-object pointer.

\section{Soundness under Live Redefinition}
\label{sec:soundness}
\textbf{Threat Model:} A converted loop assumes Tier-1 summaries hold (e.g., that \texttt{assoc} is pure). A subsequent runtime definition---\texttt{(defn assoc [c k v] (log! c) ...)} or \texttt{(defmethod assoc :around ...)}---invalidates this.

\textbf{Mechanism:}
\begin{enumerate}
    \item \textbf{Dual-path Emission:} The compiler emits optimized (fast) and original (slow) paths for each converted region.
    \item \textbf{Region Registration:} At load time, each converted region calls \texttt{(register-region)}, returning a \emph{validity cell}, and registers as dependent on every assumed standard-library name (e.g., \texttt{assoc}, \texttt{conj}).
    \item \textbf{Invalidation:} In optimizer mode, definitions for functions like \texttt{assoc} are wrapped with a call to \seqsplit{\texttt{(note-redefinition 'assoc)}}, flipping dependent validity cells for \texttt{assoc} to \texttt{invalid}. This fires whether a name is redefined outright or a generic function gains a new method (e.g., an unhandled class's \texttt{defmethod})---both treated conservatively as invalidating, since a definition's execution point can't distinguish them.
    \item \textbf{Guard Check:} The fast path is guarded by a validity-cell check, performed once at entry; if invalid, execution takes the slow path.
\end{enumerate}

\textbf{The visibility contract.} The guard provides \emph{entry-level} consistency. A region entered while its assumptions hold runs to completion under entry-fixed definitions; a redefinition becomes visible only at its next entry. \emph{Concurrent redefinition:} the invalidation write is monotonic, so a racing entry observes the old or new validity---never torn---and a stale read delays the fallback one activation. \emph{Self-inflicted redefinition:} user code inside a converted region may redefine an operator mid-activation---a semantic choice: the late-bound program observes the new definition next call; the converted region completes under its entry-time definitions. We adopt this per-region snapshot semantics---Julia's world-age visibility rule: a method defined mid-execution is invisible until control returns to a newer world \cite{belyakova2020jit}. Re-checking every iteration would buy per-iteration visibility at a cost. Under either contract the region can't crash or corrupt state: the accumulator is touched only through compiler-owned transient operations, whose behavior doesn't depend on the redefined name.

\textbf{Why the mutation itself needs no separate synchronization.} FOL is currently single-threaded, so this doesn't arise in practice; briefly, it wouldn't arise later either. Uniqueness-at-death (Lemma~\ref{lem:classifier}) establishes that no reference to the accumulator survives outside the loop's binding---not merely no \emph{same-thread} reference---so a second thread touching the same object is exactly the reference the classifier's freshness and no-aliasing premises already rule out. No additional locking would be needed if FOL later gains threads.

\textbf{Corollary (soundness of the deployed system).} Theorem~\ref{thm:sound} establishes soundness for a compile-time snapshot of $\Sigma$ alone, saying nothing about a program that later redefines an assumed name. The guard above closes that gap: every activation falls into two cases---(a) it enters under a valid cell, so Theorem~\ref{thm:sound}'s assumptions (A1--A3), held at compile time, continue to hold for the activation by the entry-snapshot visibility contract---so the theorem applies; or (b) it finds the cell invalid and takes the always-sound original path, incurring no obligation. These cases are exhaustive and mutually exclusive, so the deployed system---classifier plus guards---is observationally equivalent to the original program at every call, for any redefinition/region-activation interleaving, modulo the entry-snapshot granularity of case (a).

This mechanism provides per-name dependency tracking requiring no runtime recompilation---differing from Julia's world-age counter \cite{belyakova2020jit} (§\ref{sec:related}), though sharing its entry-snapshot visibility rule. A panic switch disabling all optimizations serves as a first line of defense.

In batch compilation mode (\seqsplit{\texttt{*sealed\_world*}}), the world is assumed closed and no guards are emitted.

\section{Implementation}
\label{sec:implementation}
The system comprises \textasciitilde2,545 lines of Common Lisp, across \texttt{summaries.lisp}, \texttt{escape-analysis.lisp}, \texttt{world.lisp}, and compiler hooks, covered by 307 checks (summary, analysis, inference, conversion suites, including regression tests for the method-combination trust check and the formal-model tag-vocabulary conformance check, §\ref{sec:formal}); the project suite (3,390 checks) passes at 100\%.

\textbf{Fidelity to the formal model.} §\ref{sec:formal}'s rules are a description of \texttt{escape-analysis.lisp}, not an independent specification checked against it after the fact---so the correspondence needs an argument, not just narrative claims. Table~\ref{tab:fidelity} maps every rule to the code implementing it, verified against the current source rather than written from memory; auditing this mapping directly surfaced two rules genuinely missing from an earlier draft of Figure~\ref{fig:side-conditions}/\ref{fig:formal-rules} (\textsc{chain-id}, \textsc{exit-update}, discussed there) before we added them---evidence the exercise catches real gaps, not just typos. The single-\texttt{walk} implementation fuses $\mathrm{RefersTo}$-checking into the main judgment rather than computing it as a separate pass (a node either matches a rule or recurses; the generic fallback at the bottom is \textsc{none}/\textsc{escape} together, distinguished only by whether $acc$ occurs in the unmatched subtree)---a fusion optimization, not a fidelity gap, since $\mathrm{RefersTo}$'s own definition (Figure~\ref{fig:side-conditions}) is exactly "occurs syntactically," which the fallthrough re-derives structurally. This mapping is not merely asserted: a regression test (\texttt{escape-analysis-suite}, \texttt{tag-vocabulary-matches-formal-model}) collects every usage tag \texttt{classify-loop-param} actually produces across the full test and benchmark corpus and asserts the set is a subset of Table~\ref{tab:fidelity}'s vocabulary---a change that adds a classifier tag without updating this table fails CI, not just a future paper revision.

One asymmetry the audit found and left as-is, since it only strengthens soundness: \textsc{recur-reset}'s premise is $\neg\mathrm{RefersTo}(e',acc)$, but the implementation tags \texttt{:recur-reset} whenever $e'$ fails $\mathrm{Chain}(e',acc)$, \emph{whether or not} $acc$ occurs in $e'$---broader than the formal rule, not narrower, and \texttt{:recur\_in\_complex\_context}'s own trigger (an unhandled AST path to the \texttt{recur}, not $e'$'s shape) is independent of both, so the two tags can co-occur on the same node. Both remain disqualifying either way, so \emph{Qualifies} is unaffected: the implementation simply doesn't always distinguish \emph{why} a non-chain update is rejected as finely as the two named rules suggest, collapsing what would be two proof obligations into a single, more conservative check.

A key tool was \textbf{audit mode}, running the analysis against any codebase, collecting convertible-site counts, disqualification reasons, and op-gate statistics---without emitting code. It sized the opportunity and guided precision before we wrote the rewriter. The audit on LSim's core (\texttt{lsim.fol} + \texttt{lsim-pq.fol}, 614 lines) shows 5 loops with 3 accumulator candidates, all qualifying, and that Tier-1 summaries covered 61.3\% of 447 call sites, the remainder user code.

\textbf{Compile-time overhead.} The analysis is a single-pass, per-form cost, not a whole-program fixed point (Tier-2's, bounded per function, §\ref{sec:tier2}), so we expect it cheap relative to the front end. We measured: compiling the same 614-line LSim source (5 audited loops) with all five off takes $2.58\pm0.09$\,ms of \texttt{compile-form} time; with all five on, $10.22\pm0.76$\,ms (mean $\pm$ sample stddev, 8 trials, same machine and session as RQ2). This $3.97\times$ ratio is front-end-only---it excludes SBCL's downstream native-code compilation, dominating build time identically---and the overhead (about 8\,ms for 614 lines) is unnoticeable in an edit-compile-test loop.

\section{Evaluation}
\label{sec:eval}
We evaluate our work via eight research questions. Every figure in this paper, including RQ5's ablation and RQ6/RQ7's LSim measurements, was measured on the same machine---an AMD Ryzen 5 7430U (single-threaded) with SBCL 2.6.0 (1\,GB dynamic space)---superseding an earlier version of this paper that mixed this machine's RQ2 figures with RQ5/RQ6/RQ7 measurements from a separate development machine (Ryzen 9 5900X); Threats to Validity discusses what changed on re-measurement and why. To reduce between-invocation drift (a laptop-class part's thermal/scheduler variation isn't captured by trial-to-trial stddev), the harness runs a three-second preflight warm-up, three warm-up calls per workload, and a two-second idle cooldown after each. Microbenchmark workloads (Table~\ref{tab:microbenchmarks}) use 30 timed calls each (originally 5 for the three large rows, widened to match the small-N rows' power); whole-program workloads (Table~\ref{tab:programs}) use five, except LSim's re-measurement, which also uses 30 given how close to 1$\times$ its ratios sit. Each timed call is preceded by a forced collection, reported as mean $\pm$ sample stddev, with per-call allocation from the runtime's bytes-consed counter. The ``Off'' column disables \emph{every} optimization flag (transient conversion, scalar replacement, numeric specialization, dynamic-extent closures, optimized constructors); ``On'' enables all five, i.e.\ the pipeline a deployed build runs, not transient conversion alone. RQ7 confirms disabled emission is byte-stable vs.\ the pre-work compiler (\texttt{v0.1.1}). We inspected emitted code to see which of the other four flags fire, avoiding misattribution: scalar replacement and optimized constructors never fire (no record classes); numeric specialization fires on every workload but word-count, unboxing each loop counter---never the accumulator, whose type is unprovable; dynamic-extent closures fire on the two \texttt{reduce}-based workloads, stack-allocating the literal fold function. The reported numbers thus reflect transient conversion's effect plus these verified contributions, not conversion alone or five optimizations compounding uniformly. Deterministic allocation ratios agree across old and new measurements where both exist.

\textbf{RQ1: Correctness.} Our system passes the 3,380-check suite, including ownership tests (e.g., \texttt{persistent!} freezing a transient), regression tests for the method-combination trust check (§\ref{sec:formal})---a pre-existing \texttt{:around} method on \texttt{assoc} for \texttt{<dict>} must block conversion and must not be triggered zero times by the (correctly-declined) fast path, reproducing the exact scenario that led us to add the check---and, following §\ref{sec:opgates}'s generalization of edit-tagged transients to sets, correctness tests confirming a transient set's mid-session reads and \texttt{persistent!} freeze match the persistent original exactly (source-preservation and read-after-write tests mirroring the existing dict/vector suite). LSim produces byte-identical output (event histories of 876 and 281,248 gate evaluations) with baseline and optimized compilers.

\textbf{RQ3: Tier-2 inference on recursive functions.} The fixed-point inference of §\ref{sec:tier2} is validated at the \emph{analysis} level: the inference suite verifies summaries converge for a self-recursive accumulator pattern and for mutual recursion (\texttt{is-even?}/\texttt{is-odd?}). The bounded-iteration fallback is implemented (§\ref{sec:tier2}) but untested by a non-convergent case; tested patterns converge within the bound. For \emph{recursive-helper threading}, we still report no end-to-end speedup: by the alignment discipline, an update chain must consist of operations the rewriter can replace with transient counterparts, and a user-defined helper has none. Closing this gap is future work (§\ref{sec:discussion}).

Tier-2's other consumption path---the constructor-call loop initializer (§\ref{sec:tier2})---does have a measured, causal effect. A loop initialized from a user-defined 0-ary constructor (\texttt{(loop [acc (make-cart)] ...)}), previously ineligible for conversion regardless of chain quality, converts once the constructor's Tier-2 summary is available: on the same dict-assoc workload and machine as RQ2 (200k assocs), it delivers $3.20\times$ wall-time and $8.7\times$ allocation reduction ($378.7\pm15.3$\,ms off vs.\ $118.3\pm3.3$\,ms converted; 5 trials)---matching Table~\ref{tab:microbenchmarks}'s literal-init dict row, since the rewrite itself is identical once the init is accepted. Clearing the constructor's inferred summary before compiling the loop---same source, same flags, only Tier-2's answer withheld---reproduces the \emph{Off} baseline almost exactly ($389.4\pm12.2$\,ms, i.e.\ the baseline is $0.97\times$ the ablated time), isolating Tier-2 as the cause rather than a confound.

Conversion removes 8.7--11$\times$ of allocation and closes 72--79\% of the wall-time gap to hand-written CL: the dict loop goes from 33.2$\times$ slower than a hash-table loop to 9.9$\times$; the residual is generic dispatch/boxing, which transients don't address. First, the transient rewrite's output is exactly what a Clojure programmer writes by hand (§\ref{sec:background}), with a free entry guard (RQ7); the numeric-specialization win (every row but word-count) is separate, unavailable without hand-added types. The ``On'' column is thus a fair end-to-end automation measure, not just zero-cost transients. We checked against real Clojure (200k dict assocs, 1M vector conjs, persistent vs.\ transient, OpenJDK/GraalVM 25, same machine as RQ2, 5 fresh-process trials): hand-written transients get 4.5--5.5$\times$ (dict, mean 5.2$\times$) and 3.2--4.5$\times$ (vector, mean 3.9$\times$)---the same range as FOL's automatic 3.36--3.81$\times$, not higher, since the manual port skips the entry guard and dispatch overhead our fast path carries---corroborating that automatic conversion lands near manual, not merely syntactically similar. Second, small-N loops with 3 operations per boundary are modest wins (1.33--1.36$\times$), where wrapper transients would have shown no such gap on write-only workloads but could never have converted the read-containing one at all (RQ5).

\textbf{RQ4: Profitability heuristic.} Conversion cost has two axes, not to be conflated. The first---\emph{operations per transient/persistent boundary}---is addressed by edit-tagged transients: as Table~\ref{tab:microbenchmarks} shows, even three-update boundaries are modest wins (1.33--1.36$\times$). The second is the \emph{initial size} of an accumulator starting from an already-populated collection: entering/leaving the transient protocol has constant cost, amortized once enough structure is touched. Benchmarking fixed updates against varying initial sizes locates the crossover at size 16 for dictionaries, 12 for vectors. For loops whose accumulator begins non-empty, the compiler ANDs the world guard with a runtime size check, \texttt{(< threshold (count acc))}, checked once at loop entry. Accumulators grown from an empty literal---the common, most profitable case---are always converted: their initial count never exceeds a threshold, so size-guarding would make the fast path unreachable where it pays most. Measured worst cases for unguarded empty-init loops are break-even to modest (Table~\ref{tab:microbenchmarks}), so no iteration-count guard is emitted. A loop initialized from a Tier-2-summarized constructor call (§\ref{sec:tier2}) gets the same treatment---no size guard---but for a weaker reason: its initial size isn't known to be zero, it just isn't known. A constructor building a large, pre-populated collection would convert unconditionally, without the measurement backing the empty-literal case; extending the guard to this path is future work.

\textbf{RQ5: Ablation: wrapper vs edit-tagged transients} (re-measured on the RQ2 machine; see Threats to Validity for why this supersedes an earlier, uncommitted measurement). Rather than simulate a wrapper's cost analytically, we exercised the actual alternative: FOL's runtime contains a legacy wrapper-style transient implementation for dicts/vectors/sets (hash-table/array-backed, O(n) at both \texttt{transient} and \texttt{persistent!}, no mid-session reads), unused by default---sets, in an earlier draft of this paper, used it unconditionally, before we generalized the edit-tagged treatment to them too (§\ref{sec:opgates}), and this ablation now covers all three representations, not just dict/vector. An ablation flag (\texttt{fol.compiler.collections:*wrapper-transients*}) switches which representation \texttt{transient} constructs, so the identical classifier, rewriter, and source compare two real representations, not a modeled one. On RQ2's own workloads (30 trials each): for every \emph{write-only} workload --- large (dict, vector, set) and small-N alike --- wrapper and edit-tagged are statistically indistinguishable in both time (large: 3.33--3.48$\times$ across all three representations; small-N: 1.23--1.24$\times$) and allocation (identical to three significant figures in every matched pair: 8.7$\times$ dict/set, 11.0$\times$ vector, 1.4$\times$ small-N). The O(n)-boundary cost the wrapper pays is real but, for a single large session, amortizes across every operation in that session and converges to roughly the same total work edit-tagged does; it does not reappear at small-N either, since 40{,}000 independent 3-op sessions still cross the boundary only 40{,}000 times, not enough for the constant-factor difference to dominate on this hardware. The measured, decisive edit-tagged advantage is instead exactly the \emph{structural} one: wrapper transients cannot serve a read at all, so a read-containing small-N workload stays at baseline (refused, 1.00$\times$) under the wrapper while edit-tagged converts it---1.28$\times$ for \emph{both} the dict and the set read-containing workloads, an identical figure that is itself evidence the two representations now behave the same way for the same structural reason, not a coincidence of tuning. Lowering the boundary cost from O(n) to O(1)/O(32) matters for what it \emph{enables} --- read-heavy conversion, unavailable to wrapper transients by construction --- more than for raw write throughput on the workloads we measured, a more precise and more conservative claim than our own earlier draft made.

\textbf{RQ6: Whole-program benchmarks.} Microbenchmarks isolate the accumulation loop; a whole program dilutes the win with surrounding work it doesn't touch. We measured four programs spanning accumulation-dominated to accumulation-incidental (Table~\ref{tab:programs}, same machine/protocol as RQ2; LSim as noted).

\emph{Word-count} (tally 200k tokens over 997 keys into a dict, via a \texttt{reduce} reading and updating the accumulator each step) is accumulation-dominated: conversion yields \textbf{3.5$\times$} wall-time and \textbf{17.1$\times$} allocation, running within \textbf{4.1$\times$} of a hand-written mutable hash-table loop---the read-heavy fold edit-tagged transients enable. Unlike other workloads, word-count has no loop counter, so numeric specialization doesn't apply; its fold qualifies for dynamic-extent allocation, though not the source of the dict's savings. This is the clearest evidence a whole program's runtime, not just an isolated loop, improves.

\emph{Quicksort} (partition by building two fresh child vectors in one two-accumulator loop, then recurse) is the algorithmic tier: \textbf{1.7$\times$} wall-time and \textbf{3.3$\times$} allocation. The dilution is honest---each level does unconverted reads, a \texttt{concat}, and recursion---and conversion fires at every level; the partition loop's index counter is numeric-specialized too. A destructive array sort (\texttt{cl:sort}, a different algorithm over unboxed storage) is another 16.3$\times$ faster, locating persistent quicksort's residual cost in representation, not just allocation.

The \emph{same} quicksort in the in-place-swap style---threading the input vector through the loop and updating it with \texttt{assoc}---is \emph{refused}: the threaded accumulator fails freshness (the caller's argument, not a fresh allocation), and \texttt{assoc} isn't in the vector op-gate (only \texttt{conj!}). This is the alignment discipline drawing its line inside one algorithm: the profitable style converts, the other doesn't.

\emph{Bfs-ranks} (level-order rank assignment over a 100k-node tree, via a nested \texttt{reduce} placed directly in the recur position) is a second accumulation-dominated program, the only one converting two independently-typed accumulators at once: a vector \texttt{queue} (the FIFO frontier) and a dict \texttt{ranks} (visitation order per node). Conversion yields \textbf{1.6$\times$} wall-time and \textbf{3.9$\times$} allocation, running within \textbf{2.1$\times$} of a hand-written mutable hash-table-plus-array BFS. Getting both accumulators to convert surfaced and fixed a genuine analysis imprecision: validating one accumulator's nested-reduce chain had the side effect of leaking its spine op into an unrelated second accumulator's op-gate check, wrongly failing it (§\ref{sec:chains}).

\emph{LSim} (the event simulator) is the accumulation-incidental end, and re-measuring it on the RQ2 machine (30 trials, 8bit-100 circuit, 876 gate evaluations) changed the finding, not just the numbers: transient conversion \emph{regresses} LSim rather than helping it, in both wall-time (0.75--0.89$\times$ across three independent runs; always a regression, though the exact magnitude is noisy at this circuit's sub-15\,ms scale) and allocation (0.78--0.89$\times$, deterministic and identical across runs, so more load-bearing than the time figures). Isolating transient conversion alone (the same TC-only/All-5 split as Table~\ref{tab:tc-ablation}) shows the regression is not a confound from the other four flags: TC-only already regresses (0.84--0.87$\times$ time, 0.887$\times$ alloc, both runs agreeing to three figures on allocation), and the other four flags make it \emph{worse}, not better. This is a real instance of the residual exposure RQ4 already names rather than a new failure mode: LSim's converted accumulators are small-N (2--3 operations per boundary) and called with high frequency, and per-call construction of an edit-tagged \texttt{<transient-dict>}/\texttt{<transient-vector>} instance via \texttt{make-instance} evidently costs more than it saves at this scale on this hardware---LSim's hot loop is additionally bounded by leftist-heap node churn and generic dispatch, unaddressed by this technique either way. \textbf{Benchmark provenance.} All workloads above are ours; two (\texttt{quicksort.fol}, \texttt{lsim.fol}) predate this project by 4--5 months (added 2026-02-19/25, as general FOL example programs, before the escape-analysis project began 2026-07-03) and so were not written to showcase transient conversion, but \texttt{word-count}, \texttt{bfs-ranks}, and the microbenchmarks were authored during this project specifically to evaluate it---an unavoidable co-design risk for the microbenchmarks (isolating the pattern is the point) but a real one for the whole-program workloads. To bound it, we added a fifth whole-program workload with provenance outside our control entirely: \texttt{read-element}'s \texttt{:attrs} loop from \texttt{cognitect/aws-api}, a real, independently-maintained open-source Clojure library with no connection to FOL, ported to FOL with its loop shape unchanged (only the two Java-interop reads become vector indexing, since FOL has no XML/Java interop). The site was not hand-picked for convertibility: it is one of the 102 sites the gate-faithful classifier above (not a human) flagged \texttt{:qualified} out of the full 29-project corpus, chosen for the port only because it was small enough to transcribe by hand. At the RQ2 stress-test scale (n=200{,}000) it converts for 2.5× wall-time and 8.9× allocation reduction (mean of 5, within the same range as the paper's own dict-loop microbenchmark, slightly lower because each iteration does two reads the paper's synthetic workload doesn't); at its realistic scale (5 attributes, matching typical XML element attribute counts, 30 trials) the speedup is 1.00--1.03×, indistinguishable from noise---an even more honest small-N floor than Table~\ref{tab:microbenchmarks}'s synthetic 1.34× row. Full source, driver, and the classifier run that located it are in the artifact (\texttt{benchmarks/run-external-provenance-bench.lisp}).

\textbf{RQ7: Cost when off / inapplicable.} The load-bearing evidence is deterministic, not statistical: emitted code with the flag off is byte-stable by test against the pre-work compiler (\texttt{v0.1.1}), so there's no code-generation difference for timing to proxy for. The timing figures now corroborate this at adequate power: an earlier $n=5$ comparison wasn't powered to distinguish a small difference from noise, so we re-ran both sides together in the same session as Table~\ref{tab:microbenchmarks} (30 trials each, matching the small-N rows' protocol): $388.1\pm18.0$\,ms off vs.\ $392.1\pm11.4$\,ms on \texttt{v0.1.1}---a $-4.0$\,ms difference, 95\% CI $\pm7.6$\,ms, comfortably including zero and an order of magnitude tighter than the $n=5$ comparison it supersedes. The guard's own marginal cost is now isolated directly rather than inferred from an end-to-end workload: comparing the identical transient-converted loop body compiled with the dual-path guard (\texttt{fol.compiler.world:*sealed-world*} \texttt{= nil}) against the fast path alone (\texttt{*sealed-world* = t}), called $2\times10^7$ times per trial with zero loop iterations so per-call overhead dominates loop-body work, gives a guarded/sealed ratio of 0.93$\times$ for a 1-dependency region and 1.13$\times$ for a 6-dependency region (5 trials each)---both within measurement noise of 1.0$\times$ and bouncing in opposite directions, consistent with the mechanism (§\ref{sec:soundness}): a region gets exactly one validity cell regardless of dependency-set size, so the guard is one \texttt{CAR} check independent of how many names it depends on. We no longer cite LSim for this claim: §\ref{sec:eval}'s RQ6 re-measurement found LSim regresses under conversion overall, which confounds isolating the guard's own cost from the loop body's; the direct isolation above supersedes it.

\textbf{RQ8: Live invalidation.} We tested the invalidation mechanism by running a converted loop, redefining \texttt{assoc} with side effects, and re-running it. The same function object fell back to the slow path on its next entry---per the entry-level visibility contract (§\ref{sec:soundness})---producing identical results to the original, with world-stats counters confirming only \texttt{assoc}-dependent regions were invalidated. We also tested the mechanism's other invalidation trigger, previously untested: a \texttt{defmethod} specializing an assumed name on a class the converted region had never seen, rather than a \texttt{defn} redefinition of the name itself. A fresh generic function gaining its first method behaves identically to a \texttt{defn}---the world-stats counters (\texttt{redefinitions-noted}, \texttt{regions-invalidated}) tick the same way, confirming the two triggers share one code path (§\ref{sec:soundness}) rather than one being untested happenstance.

\textbf{Applicability beyond FOL.} To estimate how often the target pattern occurs in real code, we ran a reader-level corpus analyzer (released with our artifact) over 29 open-source Clojure projects (2{,}905 files, sharing FOL's persistent collections and \texttt{loop}/\texttt{recur}/\texttt{reduce} idioms). Of 1{,}442 loop/reduce accumulator sites, 12.7\% rebuild a \emph{map} and 21.9\% grow a \emph{vector/set/list} each iteration---about a third (34.6\%) matching the targeted shape. This first pass is a \emph{necessary}-condition proxy only: it checks syntactic rebuild shape, not the classifier's actual gates (§\ref{sec:analysis}, §\ref{sec:opgates}).

We closed most of that gap: a second analyzer (same artifact, same locked corpus) ports \textsc{chain-kind}, the tail-position-sensitive usage walk, the per-representation op-gates, and the freshness rule directly---not shape-matching, the actual predicates of §\ref{sec:formal}, adapted to reader-level (non-macroexpanded) Clojure forms---and is self-tested against cases mirroring this paper's own worked examples, including a check that it refuses the DVI-style helper-threading pattern exactly as §\ref{sec:discussion} says FOL itself does. Run over the identical corpus, it \emph{measures} rather than bounds the qualifying fraction: of 1{,}166 loop/reduce \emph{forms} (the unit comparable to the 1{,}442 above; the denominator shrinks because \texttt{reduce-kv} and destructured bindings are excluded rather than scored), 8.75\% actually qualify (5.74\% at the finer per-accumulator-binding granularity, 105/1{,}830). The dominant disqualifier is \emph{freshness}, not chain shape or op-gate mismatch (0\% op-gate failures): 76--84\% of syntactically map/vector/set-shaped accumulators are threaded from an existing collection---a function parameter, a \texttt{vec}/\texttt{into}/\texttt{merge} result, a helper call---not a fresh literal or a known-fresh constructor, so the freshness precondition (§\ref{sec:tier1}) rules them out regardless of how clean the update chain is.

\emph{But not all of that 76--84\% is the same claim, and conflating them overstates the technique's structural ceiling.} We categorized every no-fresh-init binding by \emph{why} it failed (\texttt{classify.clj}'s \textsc{init-nonfresh-reason}): a bare variable or parameter as init---the quicksort-swap shape, §\ref{sec:eval}---is \emph{aliased by construction}, unfixable by any future extension of this analysis, since the value is handed in from outside the loop and nothing short of interprocedural aliasing analysis (a different technique) could ever prove it fresh. A call to \texttt{vec}/\texttt{into}/\texttt{merge}/similar, or to a project-local helper, is different in kind: the value may well \emph{be} freshly allocated at runtime, just not provably so by this classifier---an \emph{analysis gap} (extending Tier-1's fresh-constructor table, or Tier-2 inference for the helper case, §\ref{sec:tier2}, could plausibly close some of it), not a structural one. Of the 1{,}537 no-fresh-init bindings, 425 (28\%) are neither a bare reference nor a recognized call---mostly non-collection scalar loop counters bundled into the same binding vector as a real accumulator (e.g.\ the \texttt{i} in \texttt{(loop~[acc~\{\}~i~0]~...)}), noise for this question rather than failed accumulation attempts, so we exclude them from the split below. Of the remaining 1{,}112 genuine collection-init failures: 574 (51.6\%) are aliased references---the true structural ceiling---and 538 (48.4\%) are analysis gaps (439 helper calls, 99 non-fresh stdlib calls). Read together with the quicksort-swap refusal: aliased-mutation code is real and irreducible, roughly half of what freshness rules out, not the whole 76--84\%; the other half is headroom a more thorough (but not fundamentally different) analysis could still capture.

Both figures remain proxies for FOL, not measurements of it, and the second analyzer specifically \emph{undercounts} relative to full FOL along three documented axes---no macroexpansion, no helper inlining (so DVI-shaped loops always fail here, not just the specific case we hand-checked), and no Tier-2 constructor-freshness inference (a loop initialized from a project-local 0-ary constructor is always scored non-fresh here, though Tier-2 converts the FOL analogue, RQ3)---each pushing the number down, never up. Reading the two analyzers together: \textbf{5.7--8.75\% is a measured lower bound, 34.6\% a necessary-condition upper bound}, and the true FOL-side fraction likely sits above the former (helper inlining and Tier-2 recover some of what this port declines) but well below the latter (freshness alone rules out the large majority of syntactically-plausible sites). See \texttt{docs/cgo2027/corpus-study/README.md} for the full methodology and self-test.

\textbf{Threats to Validity.} \emph{Construct:} the microbenchmarks are synthetic, isolating the accumulation pattern; the small-N rows bound the worst case, not realistic mixes. \emph{Internal:} timings are wall-clock on a desktop OS; we mitigate with thirty runs for every microbenchmark row and for LSim (five for the other whole-program benchmarks), forced collections, and mean $\pm$ stddev, and deterministic allocation ratios corroborate the timing ratios. Within-run standard deviation doesn't capture between-invocation drift, and on this laptop-class machine it exceeds what the warm-up/cooldown protocol (§\ref{sec:eval}) controls for: re-measuring the identical dict-loop workload later in the same overall evaluation, after several hours of continuous compilation work on the same machine, returned a baseline 77\% higher than an earlier pass ($389.0$\,ms vs.\ $220.9$\,ms)---a far larger swing than the $\sim$5\% assumed for mitigated harnesses. So every absolute-time figure in this paper (Tables~\ref{tab:microbenchmarks}--\ref{tab:programs}, RQ3, RQ7) was re-measured together in one session for mutual consistency, rather than assembled piecemeal; but the swing itself means single-decimal time ratios should be read as indicative, not precise, beyond what five-run stddevs alone convey. Allocation ratios reproduce exactly regardless of session, hence more load-bearing. The profitability thresholds (16/12), from a separate crossover-finding sweep not re-run in this pass, are constants, not universal, and inherit the same session-dependence caveat. \emph{External:} one language, one end-to-end application (LSim, which regresses under conversion by design of its accumulators---small-N and frequently called, exactly the shape RQ4's cost model already flags as marginal; we no longer claim a real application as a positive proof point, only a correct and honestly-measured one). LSim's own regression magnitude was itself session-noisy across our three re-measurement runs (0.75--0.89$\times$ time, though allocation reproduced exactly at 0.78$\times$/0.89$\times$ across runs)---a smaller-scale echo of the same drift phenomenon discussed above, expected given its sub-15\,ms absolute scale. Most of our whole-program benchmarks were authored by us, several specifically for this evaluation (RQ6's provenance paragraph); the one workload with fully external provenance (a real \texttt{cognitect/aws-api} loop, chosen by an automated classifier run rather than by hand) lands within the same range as our own microbenchmarks, but n=1 bounds how much that generalizes. We haven't ported the classifier to a second dynamically-typed language, so portability of the \emph{analysis} beyond FOL (§\ref{sec:discussion}) remains argued, not demonstrated; the region-invalidation mechanism is on firmer footing, having been exercised by hand in plain Common Lisp with no FOL compiler involvement (§\ref{sec:discussion}), but that demonstration reuses FOL's own persistent-collection library rather than an independently-typed second language's, so it corroborates generality of the guard, not full portability of the system. Nor have we estimated what fraction of real accumulation-heavy code is interprocedural like DVI (§\ref{sec:discussion}) vs.\ the intraprocedural pattern converted here. RQ8 now confirms the \texttt{defmethod} invalidation trigger itself is mechanically sound (previously untested), but we still don't know how often CLOS method addition invalidates a dependent region under organic, sustained redefinition traffic in a real running program---RQ8 exercises one method addition, not a frequency or cost distribution. The Clojure corpus gives a bracket, not a point estimate: 5.7--8.75\% measured lower bound to 34.6\% necessary-condition upper bound (§\ref{sec:eval}), and even the tighter figure is a proxy for FOL, not a measurement of it. Every number in this paper now comes from the single RQ2 machine (Evaluation preamble), except RQ7's \texttt{v0.1.1} comparison's other side, which necessarily runs the pre-work compiler in a separate worktree on the same machine; we claim nothing about other architectures or Lisp implementations.

\section{Discussion and Limitations}
\label{sec:discussion}
\textbf{DVI does not convert---and why.} The DVI benchmark accumulates through a user-defined helper, \texttt{(add-item cart price)}, called inside a \texttt{bind}, not at \texttt{cart}'s own recur or exit position: \texttt{add-item}'s result flows through \texttt{cart-total} and a further \texttt{assoc} before the value that actually recurs (\texttt{c2}) is produced---a different local variable from \texttt{cart} itself. The classifier accordingly assigns \texttt{cart} two disqualifying uses: \texttt{:escape-call} (passed to \texttt{add-item} in a non-chain position) and \texttt{:recur-reset} (its recur slot receives \texttt{c2}, which the syntactic chain check can't know is derived from \texttt{cart}). This holds even though \texttt{add-item}'s own body qualifies for helper inlining (§\ref{sec:chains}): inlining only fires where the classifier already looks for a chain---a recur argument or the loop's tail position---and \texttt{cart}'s one use is neither.

Closing \emph{this} gap alone would not convert DVI, for two further reasons uncovered while investigating it. First, \texttt{cart} is a \texttt{<cart>} instance---a user \texttt{defclass}, not a dict/vector/set---and our transient protocol (§\ref{sec:edittagged}) has no representation for arbitrary CLOS objects: even a syntactically perfect chain would fail $\mathrm{OpGate}$'s representation lookup. Second, and more fundamentally: \texttt{<cart>} defines \texttt{(defmethod assoc :around [(cart <cart>) (slot (= :items)) val] (assoc (call-next-method) :\_total nil))}---the very "automatic derived-value invalidation" the benchmark is named for. \texttt{ASSOC!} has no connection to \texttt{ASSOC}'s method combination, so even a hypothetical CLOS-object transient representation would silently \emph{drop} this invalidation on the fast path, producing stale-cache results---exactly the A1 gap discovered and closed in §\ref{sec:formal}. Our classifier now checks for this directly ($\mathrm{Trusted}$, §\ref{sec:formal}) and would refuse \texttt{<cart>} on these grounds alone, independent of the freshness or representation issues. DVI is thus not merely unconverted by an incomplete implementation; the design we chose---trusting a name-resolution-faithful \emph{summary table} rather than re-deriving each call's full method combination---structurally cannot convert an accumulator whose defining behavior \emph{is} a custom method combination on a Tier-1 name, without either abandoning the black-box summary approach (§\ref{sec:tier1}'s whole basis for tractability in an open world) or building a mechanism to safely re-derive bang-op equivalents of arbitrary user method combinations, neither undertaken here. We motivate this paper with DVI precisely because it's the pattern we don't handle, now for a reason more principled than "not yet implemented": the chain-through-\texttt{bind} extension remains future work independent of DVI, since it would still benefit ordinary dict/vector/set accumulators threaded through helpers via intermediate locals, a case with none of \texttt{<cart>}'s two further obstacles. How common DVI's specific shape---interprocedural threading \emph{combined with} custom method combinations on the threaded value---is relative to the intraprocedural pattern we convert is unmeasured (Threats to Validity, §\ref{sec:eval}).

\textbf{Novelty, and why an open world.} We claim no new escape analysis; proving uniqueness for in-place update is classic \cite{hudak1985aggregate}. New is the \emph{assembly} and its target---automatic transient conversion in a transpiled, latently-typed language with no optimizing IR, JIT, or type system. To our knowledge, no prior system infers uniqueness-at-death automatically---without programmer-supplied ownership or linearity annotations---to license in-place update in a dynamically-typed, live-redefinable language: automatic approaches (Perceus, Koka) require static types; the dynamic-language approach (Clojure) requires manual, unchecked opt-in. This differs from JIT-based escape analysis in dynamic-language VMs generally, which infers non-escaping \emph{fresh} allocations automatically but licenses stack allocation within a frame, not in-place mutation of a persistent structure's root across loop iterations, where the value is aliasable and escapes by default. The open world isn't incidental; it creates the problem the world guard solves. A JVM language like Clojure shares the allocation pattern but doesn't redefine classes mid-run, and its JIT performs escape analysis, deoptimizing when assumptions break; our world guard wouldn't earn its keep there. Koka, a static language, attacks the same cost oppositely via reference counting/borrowing \cite{reinking2021perceus,lorenzen2023functional}, presupposing type information FOL lacks. The gap we address---transient conversion in an \emph{open-world, untyped, JIT-less} setting---is what those systems leave open; the mechanisms (name-resolution-faithful summaries, region invalidation, safe-by-abort emit-time rewriting), not FOL itself, transfer to similarly-positioned transpiled dynamic languages. We give direct, if partial, evidence for the region-invalidation half of that claim: a hand-written Common Lisp program (released with our artifact; no FOL compiler pass touches it) applies the dual-path rewrite of §\ref{sec:transformation} and §\ref{sec:soundness}'s register-region/note-redefinition/region-valid-p protocol \emph{by hand}---not classifier-derived, a programmer's own transformation---against FOL's persistent-collection and transient-protocol libraries used as ordinary CL packages, and exhibits the same register~$\to$~redefine~$\to$~invalidate~$\to$~fallback sequence as RQ8, including a correct result after fallback and \texttt{world-stats} counters matching prediction exactly. This corroborates that the guard mechanism is general CLOS machinery---it consults only a string key, never the AST---not an artifact of code generation; it does not, on its own, port the classifier (§\ref{sec:analysis}), which is FOL-AST-specific by construction and is instead addressed for Clojure by the corpus study above.

\textbf{Profitability.} Our small-N wins are modest, bounded by the transient machinery's constant-factor costs. The profitability heuristic (RQ4) confines conversion of populated-collection accumulators to sizes above the measured crossover (16 for dictionaries, 12 for vectors); accumulators grown from an empty literal---the most profitable shape---are always converted. The residual exposure: an empty-init loop with few updates; we originally described measured cases as break-even to modest and accepted this over an iteration-count guard---RQ6's LSim re-measurement now shows this exposure is not merely theoretical, regressing 0.75--0.89$\times$ on a real application whose accumulators are exactly this shape (small-N, called frequently). We still accept it over an unconditional iteration-count guard, since LSim's own qualifying loops are few (§\ref{sec:implementation}'s audit) and the guard would cost every empty-init loop a runtime size check to protect a minority---but this is now a considered trade-off against a measured cost, not an assumed one. A second, currently unguarded exposure: a Tier-2-summarized constructor-call init (§\ref{sec:tier2}) gets no size check at all, since its initial size is unknown rather than known-zero (RQ4)---a large pre-populated result would convert unconditionally.

\textbf{Completeness.} Transient vectors only support \texttt{conj!} (no \texttt{assoc}); the vector-trie representation this is built on has no O(1)/O(32) in-place update-by-index counterpart to extend it with, unlike dicts/sets' HAMT, so this is a genuine representation limit, not merely unimplemented. Sets, by contrast, were wrapper-style (no reads) through an earlier draft of this paper for no such reason---\texttt{<set>} is HAMT-backed exactly like \texttt{<dict>} (§\ref{sec:edittagged}), so building the identical edit-tagged treatment for it was a direct generalization, not new design; §\ref{sec:opgates} now reflects it. Op gates make remaining limitations completeness issues, not correctness ones: they refuse converting loops with unsupported operations rather than emitting code that would misbehave.

This work climbs three rungs of increasingly precise invalidation: all-or-nothing conservative invalidation; per-name dependency tracking, scoped to only the regions a redefinition affects and made safe without recompilation by §\ref{sec:soundness}'s world guards; and summaries whose coverage---and dependency tracking---extends via inference from the standard library to user code (§\ref{sec:tier1}--§\ref{sec:tier2}). Future work could add finer rungs: distinguishing monotonic redefinitions (e.g., a generic-function method that doesn't affect existing dispatch) from truly invalidating ones, and tripwire-based recompilation instead of a permanent fallback.

\section{Related Work}
\label{sec:related}
\textbf{Perceus/FBIP.} Reinking et al. \cite{reinking2021perceus} and Lorenzen \& Leijen \cite{lorenzen2023functional} introduced compile-time lifetime analysis and ownership types enabling FBIP. We achieve this in a dynamically typed language without type-system annotations, handling a live, redefinable image. At the mechanism level, they converge more than the type-system framing suggests: Perceus's reuse analysis inserts a reuse-token check so a freed cell's storage can be claimed by an immediately-following allocation; our edit-tagged transients use an analogous token (the edit tag, §\ref{sec:edittagged}) deciding in-place-mutate-vs-copy at each write. The difference: where the check lives. Perceus pairs a static \emph{may-reuse} analysis with a per-cell runtime check; we pair a static \emph{must-be-unique} proof with a token minted per transient region, never rechecked per write---trading Perceus's per-cell runtime cost for a per-region compile-time one.

\textbf{Clojure.} Our transient protocol builds on the edit-token design Hickey pioneered in Clojure \cite{hickey2009clojure}. The key difference: Clojure's transients are manual, opt-in, and potentially unsafe; ours is automatic and sound. Our work draws on the persistent-data-structure literature of Bagwell \cite{bagwell2001ideal} and Steindorfer \& Vinju \cite{steindorfer2015optimizing}.

\textbf{World Age.} Julia's world age \cite{belyakova2020jit} invalidates code from changes to method tables. As noted in §\ref{sec:soundness}, we differ in what's protected (uniqueness facts vs. dispatch), granularity (region vs. method), and invalidation (dependency tracking vs. a monotonic counter), avoiding runtime recompilation.

\textbf{Escape Analysis.} We descend from escape analysis \cite{blanchet2003escape, choi1999escape, stadler2014partial}, but our client differs: unlike stack allocation, we target uniqueness-at-death to enable persistent-data-structure mutation. Unlike interprocedural analyses, our boundary policy relies on trusted, name-resolution-faithful summaries---more practical in a dynamic language where whole-program analysis is infeasible.

\textbf{Linear and Uniqueness Types.} Unique, unaliased values date back to linear and uniqueness types \cite{wadler1990linear}. Systems like Clean and Rust use type systems to enforce these properties; we provide uniqueness's benefits for a common pattern without type-system obligations.

\textbf{Runtime uniqueness and the aggregate update problem.} Establishing an aggregate is unaliased at update time predates persistent tries: Hudak and Bloss's \emph{aggregate update problem} \cite{hudak1985aggregate} sought uniqueness-at-death for functional arrays, combining abstract interpretation with run-time reference counts. Two designs make the uniqueness check dynamic: Swift's copy-on-write collections consult the reference count per mutation via \texttt{isKnownUniquelyReferenced} \cite{swift2023cow}; Lean's runtime reuses reference-count-one cells via compiler-inserted reset/reuse pairs \cite{ullrich2019beans}. Our classifier is the static counterpart: it proves uniqueness at compile time, eliminating the per-operation check---at the price of conservatism and world guards a dynamic check doesn't need.

\textbf{Deforestation.} The "reduce init-threading" concept (§\ref{sec:chains}) is a form of deforestation \cite{wadler1990deforestation}: an intermediate structure (the inner reduce's result) is eliminated by threading the accumulator through it.

\section{Conclusion}
\label{sec:conclusion}
We present a system for automatically and safely converting accumulation loops into in-place updates in a dynamic, persistent-first language. Combining uniqueness-at-death analysis, a construction-aligned rewriter, and a lightweight live-redefinition guard, we achieve performance gains on targeted workloads. Our honest cost model and negative results mark the technique's boundaries: edit-tagged transients are crucial for profitability. The two-tier summary design reaches into user code, including helpers; future work extends inference to multi-clause, higher-order functions, plus monotonic-redefinition/tripwire-recompilation.

\section{Proof Sketch for the Soundness of Conversion Theorem}

The proof of Theorem~\ref{thm:sound} proceeds by bisimulation. We define an operational semantics for the original (Source) and transformed (Target) programs, showing their observational equivalence. Throughout we assume A1--A3 (§\ref{sec:formal}): A2 justifies each per-operation step below; Lemma~\ref{lem:classifier} supplies the uniqueness invariant the relation maintains.

\subsection{Semantics}

We model program execution with a state $\langle e, \rho, \sigma \rangle$, where $e$ is the expression, $\rho$ is an environment from names to locations, and $\sigma$ maps locations to values.

\begin{itemize}
    \item \textbf{Values:} $v ::= l | n | \dots$ where $l$ is a location in the store.
    \item \textbf{Store:} $\sigma: l \mapsto v$. Collections are heap-allocated objects: a persistent map is $\text{Map}(\text{root})$; a transient map $\text{TMap}(\text{root}, \text{tok})$, where $\text{tok}$ is a unique ownership token.
    \item \textbf{Source Semantics (Persistent):} An update \texttt{(assoc m k v)} evaluates to a \emph{new} location $l'$ for a new map: the store $\sigma$ extends to $\sigma' = \sigma \cup \{l' \mapsto \text{Map}(\text{new\_root})\}$, leaving the original map at $\rho(m)$ unchanged.
    \item \textbf{Target Semantics (Transient):} An update \texttt{(assoc! m k v)} \emph{mutates} the map at $\rho(m)$: if the node to change has the correct token, it's modified in-place; otherwise it's copied, tagged, mutated. The store $\sigma$ becomes $\sigma'$, with the object at $\rho(m)$ modified. \texttt{(persistent! m)} "freezes" the transient, creating a new persistent map and clearing the token.
\end{itemize}

\subsection{Bisimulation Relation}

We define a bisimulation relation $\approx$ between a Source state $S = \langle e_S, \rho_S, \sigma_S \rangle$ and a Target state $T = \langle e_T, \rho_T, \sigma_T \rangle$. We write $S \approx T$ if:

\begin{enumerate}
    \item $e_S$ is syntactically identical to $e_T$ outside the converted loop; inside it, $e_S$ and $e_T$ correspond via transformation rules (e.g., \texttt{assoc} vs. \texttt{assoc!}).
    \item The environments $\rho_S$ and $\rho_T$ map the same variables to corresponding locations, except for the accumulator $acc$.
    \item The stores $\sigma_S$ and $\sigma_T$ are equivalent for locations reachable from $\rho_S$ and $\rho_T$, according to a value relation $\approx_v$.
\end{enumerate}

The value relation $v_S \approx_v v_T$ holds if:
\begin{itemize}
    \item $v_S$ and $v_T$ are identical scalars.
    \item $v_S$ is a persistent collection $\text{Map}(r_S)$, $v_T$ a persistent collection $\text{Map}(r_T)$, structurally identical.
    \item $v_S$ is the persistent accumulator $\text{Map}(r_S)$ at location $l_{acc\_S}$, $v_T$ the transient accumulator $\text{TMap}(r_T, \text{tok})$ at $l_{acc\_T}$, structurally identical (ignoring the token).
\end{itemize}

Crucially, for the accumulator $acc$, $\rho_S(acc)$ must be the \emph{only} reference to the map there---guaranteed by the uniqueness-at-death analysis.

\subsection{Proof Sketch by Induction on Evaluation Steps}

If $S \approx T$ and the Source program takes a step $S \rightarrow S'$, then the Target program can take a step $T \rightarrow T'$ such that $S' \approx T'$.

\textbf{Base Case: Loop Initialization.}
\begin{itemize}
    \item Source: \texttt{(loop [acc (hash-map)] ...)} evaluates to a state where $\rho_S(acc)$ points to a fresh, unaliased map $m_S$.
    \item Target: \texttt{(loop [acc (transient (hash-map))] ...)} evaluates to a state where $\rho_T(acc)$ points to a fresh transient map $m_T$ with a new token.
    \item States related: $m_S \approx_v m_T$, uniqueness holding in the Source.
\end{itemize}

\textbf{Inductive Step: Inside the Loop.} Consider the loop body's evaluation.

\begin{itemize}
    \item \textbf{Case 1: Read operation \texttt{(get acc k)}.}
    \begin{itemize}
        \item Source: Reads from the persistent map at $\rho_S(acc)$.
        \item Target: Reads from the transient map at $\rho_T(acc)$; transient-aware reads correctly interpret the mix of original/copied-on-write nodes.
        \item Equivalent structures return equivalent values, leaving $S'$ and $T'$ in relation.
    \end{itemize}
    \item \textbf{Case 2: Update operation \texttt{(recur (assoc acc k v))}.}
    \begin{itemize}
        \item Source: \texttt{(assoc acc k v)} evaluates to a \emph{new} location $l_S'$ with a new map $m_S'$; the old map at $\rho_S(acc)$ is now garbage (last-use property), and \texttt{recur} rebinds $acc$ to $l_S'$, maintaining uniqueness for the new value.
        \item Target: \texttt{(assoc! acc k v)} \emph{mutates} the transient map at $\rho_T(acc)$ in-place; \texttt{recur} rebinds $acc$ to the same location.
        \item The new map $m_S'$ and mutated map at $\rho_T(acc)$ are structurally equivalent, so $S'$ and $T'$ remain in relation, invariant maintained.
    \end{itemize}
    \item \textbf{Case 3: Exhaustiveness (no other use forms need a case).}
    \begin{itemize}
        \item This is a \emph{corollary} of Lemma~\ref{lem:classifier}, not an independent claim proved here: the bisimulation is defined only for \emph{Qualifies}-satisfying programs, and \emph{Qualifies} requires every occurrence of $acc$ to be a sanctioned use---each of which Lemma~\ref{lem:classifier} already places into Case 1 (read), Case 2 (update), or a loop exit. Concretely, an unsanctioned use like \texttt{(some-func acc)} with an unknown \texttt{some-func} would already violate \emph{Qualifies}'s premise, so such a loop is never accepted by the classifier in the first place---there is no transformation, and hence no bisimulation, for which Case 3 would need to say anything.
    \end{itemize}
\end{itemize}

\textbf{Inductive Step: Loop Exit.}
\begin{itemize}
    \item Source: The loop exits, returning the final persistent accumulator $m_S$.
    \item Target: The expression is wrapped with \texttt{(persistent! acc)}, which evaluates the transient $m_T$ to a new persistent map $m_T'$.
    \item Since $m_S \approx_v m_T$ before the exit, final results $m_S$, $m_T'$ are structurally identical, observationally equivalent to the rest of the program.
\end{itemize}

\textbf{Conclusion.} By induction, for any number of evaluation steps, Source and Target programs remain in relation. Since the initial states are related and the relation preserves termination and values, the transformed program is observationally equivalent to the original. Soundness rests on the uniqueness-at-death classifier's guarantees.
