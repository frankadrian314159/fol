### Title (working)

**"Transients Without Tears: Automatic In-Place Conversion of Persistent
Data Structure Updates in a Dynamic Language"**

(Alternatives to consider: "Functional-But-In-Place Without Ownership
Types"; "Uniqueness-at-Death: Sound Transient Conversion under Live
Redefinition".)

### Thesis, in one paragraph

Persistent-first languages pay a large allocation tax on accumulation
loops. Languages like Koka eliminate it with ownership types (Perceus/FBIP);
Clojure asks the programmer to opt in manually with transients. We show the
optimization can be made *automatic and sound* in a latently-typed language
with open-world CLOS dispatch and live redefinition — with no type system —
via (1) a tail-position-sensitive *usage classification* that establishes
uniqueness-at-death of loop and fold accumulators, (2) a rewriter aligned
with the classifier *by construction*, targeting edit-tagged in-place
transients, and (3) *world-guarded regions* that keep the optimization sound
when definitions change at runtime. The result: 4.1–7.6× on
accumulation-bound code, byte-identical outputs on a production-scale event
simulator, zero measured cost when disabled or inapplicable, and an honest
cost model of when transient conversion pays.

### Contribution list (state verbatim-ish in the introduction)

1. **Uniqueness-at-death by usage classification.** A flow- and
   tail-position-sensitive classification of accumulator uses
   (`:recur-update`, `:exit-bare`, `:exit-in-literal`, `:read-ok`, and the
   disqualifiers) that establishes when a persistent accumulator may be
   converted to an in-place transient — without ownership or linear types.
   Includes chain recognition through `->` threads, if-branches, and
   *reduce init-threading* (a fold that linearly threads the accumulator is
   itself a chain link).
2. **Alignment-by-construction between analysis and transformation.** The
   classifier refuses to qualify anything the rewriter cannot reach
   (`:recur-in-complex-context`) or that would change representation
   mid-loop (`:recur-reset`); per-representation *op gates* ensure converted
   code can never hit an unsupported operation at runtime.
3. **Name-resolution-faithful summaries.** The stdlib summary table (Tier 1)
   matches operators exactly the way the compiler itself resolves them
   (by name, with per-compilation-unit exclusions) — the analysis is
   provably no less sound than the language's own resolution model.
4. **Soundness under live redefinition without world-age infrastructure.**
   Converted regions compile to guarded dual paths; validity cells register
   at load time indexed by assumed names; definitions notify at execution
   time and invalidate exactly their dependents. Guards measure as free.
   (Delta vs Julia's world age [Belyakova et al., OOPSLA 2020]: we protect
   escape/uniqueness facts rather than method dispatch, at region rather
   than method granularity, and need no runtime recompilation.)
5. **An honest empirical cost model.** Wrapper transients (O(n) boundaries)
   win only at large ops-per-boundary; edit-tagged transients (O(1)/O(32)
   boundaries, token-based copy-on-write, reads supported) extend the win to
   small-N accumulations and read-heavy folds. We quantify both, including
   the negative spaces (a benchmark with zero convertible sites, and an
   end-to-end system whose hot loop is bounded by node churn the technique
   does not address).

### Paper outline (12 pages + references, ACM acmart/sigplan, anonymized)

**1. Introduction** (~1.25pp)
- The persistence tax with measured motivation: FOL benchmark suite
  overheads vs handwritten mutable CL — diff 114× (55× memory), guards 23×,
  DVI 20× time / **900× memory** with O(N²) GC pressure, LSim 7×.
- The accumulation pattern: `(loop [acc {}] ... (recur (assoc acc k v)))`
  and `(reduce (fn [acc x] (conj acc ...)) [] coll)`.
- Why existing answers don't transfer: Perceus needs ownership types;
  Clojure transients are manual and unsafe if misused; no static types
  here, and the method table can change *while optimized code is live*.
- Contributions (above).

**2. Background and a Motivating Walk-through** (~1.25pp)
- FOL in one column: persistent vectors (32-way trie + tail), HAMT dicts,
  loop/recur, `->` threading, reduce; compilation model (per-form transpile
  to CL, name-based stdlib resolution at emit/load — this fact is
  load-bearing for §3.3 and discovered the hard way; see design doc §4).
- Worked example: `lh-pop-batch` from the event simulator — accumulator
  built by `conj`, exiting inside a tuple literal `[acc q]`; show the
  converted output with `transient`/`conj!`/`persistent!` and the guard.
- Clojure transient semantics recap; why reads matter (wrapper
  representations forbid them; edit-tagged ones don't).

**3. The Analysis** (~2.25pp)
- 3.1 Two properties: escape (may) vs uniqueness-at-death (must);
  uniqueness-at-death = freshness ∧ no-aliasing ∧ last-use.
- 3.2 Tier-1 summaries: the effect lattice
  (`:none < :invoked < :shared-with-result < :retained`), ~75 hand-verified
  entries, the **root-level convention** (persistent ops build fresh roots
  referencing children — sound for all clients because the transient
  protocol is copy-on-write and elements are never mutated).
- 3.3 Name-resolution faithfulness: fol.core exports nothing; user-package
  `assoc` reads as `CL:ASSOC` or a fresh local symbol; the compiler resolves
  stdlib calls by name (`+standard-fol-functions+`); Tier-1 matching mirrors
  that resolution with `*file-function-defs*` exclusions. State the
  faithfulness argument as a small lemma: any program the analysis
  misjudges is a program the compilation model itself already resolves the
  same way.
- 3.4 The classifier: sanctioned-use grammar; tail-position propagation
  rules (if/do/bind/case/cond, literals); recur handling; nested loops and
  closures; the two alignment disqualifiers (`:recur-reset`,
  `:recur-in-complex-context`); read sanctioning (position-0 of a
  whitelisted read op only — an accumulator used as a *key* changes value
  semantics).
- 3.5 Chains: direct calls, `->` threads, if-branched chains, and **reduce
  init-threading**: `(reduce (fn [a x] <linear>) <chain> coll)` is an
  `:update` link when the lambda qualifies under fold rules and does not
  capture the outer accumulator; inner ops/reads flow into the same op/read
  sets so gates apply transitively.
- Formal core (keep to ~0.75pp): syntax of the accumulator-use judgment,
  the qualification rule, and the statement (proof sketch in appendix /
  extended version): *if every use is sanctioned, replacing the persistent
  ops by their transient counterparts and inserting persistent! at exits
  yields an observationally equivalent program* (bisimulation against a
  store semantics; the transient protocol's ownership tokens discharge the
  interior-sharing obligations).

**4. The Transformation and the Transient Representation** (~1.75pp)
- 4.1 Rewriter: transient init at binding, bang-op chains at recur
  positions, persistent! at every exit (bare / chain / in-literal); `:loop`
  vs `:reduce` modes (folds thread the transient with no inner boundaries);
  structure sharing for untouched subtrees.
- 4.2 Per-representation op gates: dict {assoc!, dissoc!}+reads, vector
  {conj!}+reads, set {conj!, disj!} no reads; incompatible chains are left
  unconverted — converted code can never hit an unsupported op.
- 4.3 Edit-tagged transients: token-based COW HAMT (`ensure-editable`,
  freeze-on-persistent!), Clojure-style vector transient (owned tail,
  O(32) boundaries); transient-aware reads (a plain persistent lookup
  *silently misreads* edited subtrees — call this out); ownership
  soundness (sources preserved across generations, tested).
- 4.4 Dynamic-extent closures (breadth client): literal `fn` at position 0
  of verified non-retaining eager HOFs stack-allocates, world-guarded
  because a retaining redefinition would dangle a stack object.

- Formal core (keep to ~0.75pp): We formalize the analysis for a core
  calculus. The key judgment, `Γ; Σ ⊢ e ⇓ U`, states that expression `e` has
  usage `U` in context `Γ` given operator summaries `Σ`. We show that "messy"
  implementation features are sound elaborations: `->` threads and `if`-branched
  chains desugar into nested applications that the core rules handle;
  name-resolution faithfulness is a property of how `Σ` is constructed, not the
  rules themselves. The main theorem (proof sketch in appendix) states that if
  an accumulator qualifies, the transient-converted program is observationally
  equivalent to the original (via bisimulation against a store semantics).

**5. Soundness under Live Redefinition** (~1.25pp)
- Threat model: converted code bakes in Tier-1 meanings; a later
  `(defn assoc ...)` or `(defmethod assoc :around ...)` changes them.
- Mechanism: dual-path emission; `register-region` at load time returns a
  validity cell indexed under each assumed name; `note-redefinition`
  (emitted as a prog1-trailer on definitions, *in optimizer mode only* so
  flag-off output is byte-stable) fires at definition-execution time and
  flips exactly the dependents; panic switch as rung 1; in-flight
  iterations complete on their entry path (sound: converted regions touch
  the accumulator only through compiler-owned ops).
- The invalidation ladder and what is deliberately deferred: the monotonic
  fast path needs user-summary inference; snapshot calls/tripwire
  recompilation are future work. Measured: guards are free (see §7).
- Batch mode (`*sealed-world*`): whole-file snapshot needs no guards.

**6. Implementation** (~0.75pp)
- ~2,300 lines across summaries / escape-analysis / world + compiler hooks;
  audit mode (analysis runs against any codebase with counters and zero
  emission changes) — used to make the go/no-go decision and to size the
  opportunity before any emit work; 192 new tests (3,248 total, 100%).
- The audit numbers as methodology: LSim = 17 loops, 9 accumulator
  candidates, 9 qualified after precision work; Tier-1 covers 54.8% of 542
  call sites with the residual all genuine user code; DVI = 0 candidates
  (see §8).

**7. Evaluation** (~2.5pp) — organize by research questions.
- **RQ1 Correctness.** 3,248 checks; LSim simulation outputs byte-identical
  (876 and 281,248 gate evals; full event histories string-equal) across
  baseline/converted and across versions; ownership tests.
- **RQ2 Speedup on accumulation-bound code** (vs the pre-work v0.1.1 tag,
  measured from a clean worktree, best-of-3, SBCL 2.6.0, Ryzen 9 5900X):

  | workload | v0.1.1 | optimized | time | memory |
  |---|---|---|---|---|
  | dict loop, 200k assocs | 224.6ms / 223MB | 55.2ms / 26MB | **4.07×** | **8.7×** |
  | vector loop, 1M conjs | 309.9ms / 352MB | 41.0ms / 32MB | **7.56×** | **11.0×** |
  | reduce, 500k conjs | 324.1ms / 359MB | 48.8ms / 40MB | **6.64×** | **9.1×** |
  | small-N (3 assocs/boundary) | 130.9ms / 127MB | 116.9ms / 99MB | **1.12×** | 1.3× |
  | small-N with reads | 174.8ms / 151MB | 135.3ms / 99MB | **1.29×** | 1.5× |

- **RQ3 Ablation: wrapper vs edit-tagged transients.** dict 2.30×→4.14×,
  vector 5.60×→7.52×, small-N ~1.0×→1.16×, reads unconvertible→1.38×.
  Present as the cost-model validation: boundary cost O(n)→O(1)/O(32).
- **RQ4 End-to-end (LSim event simulator, 8bit-100 ×20 and 8x32-900 ×10;
  32x32x32-30000 excluded for time).** 1.01× / 1.04× wall, allocation
  −180MB/run (1.10×) on 8x32-900; explain via the cost model: per-gate
  accumulations are small-N (2–3 entries), and the residual is leftist-heap
  node churn + generic dispatch, outside this technique's scope. 2 loops +
  3 folds convert automatically (init-threading captured the nested
  per-gate reduce).
- **RQ5 Cost when off / inapplicable.** Flags-off equals v0.1.1 within
  noise on every workload (e.g. 225.2 vs 224.6ms); emission is byte-stable
  by construction and by test. Guards: 1.02× with vs without on LSim —
  unmeasurable.
- **RQ6 Live invalidation.** Compiled converted loop → redefine `assoc` →
  same function object returns identical results on the fallback path;
  world-stats counters demonstrate per-name dependency precision.
- Threats to validity: single implementation/machine; microbenchmarks are
  synthetic; LSim is one real system; sxhash-collision path shared with
  the pre-existing bulk loader.

**8. Discussion and Limitations** (~0.75pp) — the honest section; keep it.
- **DVI, the motivating benchmark, does not convert** (0 candidates): its
  accumulator crosses user-function boundaries every iteration and is read
  through user functions — intraprocedural conversion cannot reach it.
  What it needs: Tier-2 (inferred/contracted user summaries) — future work,
  connects to the monotonic fast path.
- Small-N wins are bounded by per-boundary constants; a profitability
  heuristic (runtime size threshold) is possible but unimplemented.
- Sets remain wrapper transients (no reads); vector transients support
  conj! only (op gates make this a completeness, not correctness, limit).
- Rung 3/4 of the world ladder; scalar replacement and the generalized
  per-binding lattice.

**9. Related Work** (~1pp)
- FBIP / Perceus: Reinking et al. PLDI 2021; Lorenzen & Leijen FP²
  (ICFP 2023). Ours: no ownership types, dynamic language, live image.
- Clojure transients (manual; our protocol builds on the same edit-token
  design) — Hickey; persistent structures: Bagwell; Steindorfer & Vinju
  CHAMP (OOPSLA 2015).
- World age: Belyakova et al. OOPSLA 2020 (delta stated in §5).
- Escape analysis lineage: Blanchet (POPL/TOPLAS), Choi et al. (OOPSLA
  1999), Kotzmann & Mössenböck; Go's escape analysis; partial escape
  analysis, Stadler et al. (CGO 2014) — ours differs in the *client*
  (uniqueness for persistence) and the boundary policy (trusted summaries
  faithful to name resolution, not interprocedural inference).
- Linear/uniqueness types: Wadler; Clean; Rust — the contrast is the
  absence of any type system obligation on the programmer.
- Deforestation/fusion (Wadler) for the reduce-threading flavor.
